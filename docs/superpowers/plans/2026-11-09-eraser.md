# Eraser Implementation Plan (spec + plan)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers-extended-cc:subagent-driven-development. Steps use checkbox (`- [ ]`) syntax.

**Goal:** An Eraser tool that cuts away the part of a drawn line it passes over, and removes whole fills, symbols, text and leaders it touches, in the Map, Profile and Cross Section; a stylus's eraser end does the same.

**Architecture:** The geometry is pure TypeScript (`apps/web/src/lib/erase.ts`): given the lines shown in a view (in that view's metres), the eraser's path and radius, it answers which lines go, which are reshaped, and which new pieces appear. One new engine call (`erase_lines`) applies that answer as ONE undoable edit, reusing the existing stroke functions so pieces keep their type, style, flip, tags and trip. Each view collects the eraser's path during a drag and applies it on release.

**Tech Stack:** Rust (crates/cave-draw, crates/cave-wasm), Svelte 5 + TypeScript (apps/web), node `--experimental-strip-types` checks, `cargo test`.

**User decisions (already made):**
- Request: "An Eraser tool ... would cut lines drawn and whole hatches and symbols."
- Pen eraser end: "Yes, same as Eraser (Recommended)" — the stylus eraser cuts like the tool (today it deletes whole lines).
- Size: "Size slider, on the page (Recommended)" — millimetres on the printed page, circle under the cursor.
- Design: "Yes, build it" — Draw-tab button in an Erase group; cut lines; whole fills/symbols/text/leaders; one drag = one undo.

## Behaviour (the spec)

- **Lines** (any kind that is not a fill, symbol, `text` or `callout`): every part within the eraser's radius of its path is removed. What remains becomes separate lines; the longest piece keeps the original line (same id); the others are new lines copying the original's type, view, run/station, style, flip, tags and trip. A closed line that is cut becomes open. Pieces shorter than a quarter of the radius are dropped.
- **Fills** (`isFillKind`): removed whole when the path crosses or enters the area or comes within the radius of its outline.
- **Symbols, text, leaders** (`isStampKind`): removed whole when the path comes within the radius of any of their points (a symbol's two points are its anchor and aim).
- Only lines the view is showing can be erased (hidden types are left alone, as today).
- One drag = one undoable edit; nothing changes until the pointer is released. A drag that touches nothing changes nothing.
- Size: option `eraserSize`, 1–20 mm on the page, default 4 mm; radius in metres = mm × (drawing scale N) / 1000 / 2 (the size is the circle's diameter).

### Task 1: Erase geometry (pure TS)

**Goal:** `eraseLines` computes the outcome of one eraser drag.

**Files:** Create `apps/web/src/lib/erase.ts`, `apps/web/tests/erase.check.ts`; modify `apps/web/package.json` (`test:erase`, added to `test`).

**Acceptance Criteria:**
- [ ] A straight line crossed in the middle → original id edited to the longer side, one add for the other side, cut ends exactly at the circle's edge (±1e-6).
- [ ] A line wholly inside the radius → removed. A line not touched → absent from the result.
- [ ] A closed square cut on one side → one open line (edit) running the rest of the way round, no add.
- [ ] A fill whose outline the path enters, or that the path lies wholly inside → removed. A symbol within reach of its anchor → removed; text and callout the same.
- [ ] Widths, when a line has them, are cut and interpolated with the points.
- [ ] `npm run test:erase` prints `erase ok`.

**Verify:** `cd apps/web && npm run test:erase` → `erase ok`

**Interface:**
```ts
export type Pt = [number, number];
export type EraseLine = { id: string; kind: string; points: Pt[]; widths?: number[] | null; closed?: boolean };
export type EraseResult = {
  remove: string[];
  edits: { id: string; points: Pt[]; widths: number[] | null }[];
  adds: { from: string; points: Pt[]; widths: number[] | null }[];
};
export function eraseLines(lines: EraseLine[], path: Pt[], radius: number): EraseResult;
```
**Method:** distance from a point to the eraser path (polyline; a one-point path is a dot) ≤ radius ⇒ erased. For a line, walk each segment; split it at every crossing of the erased/kept boundary, found by bisection (40 steps) along the segment, after sampling the segment every radius/4 to find sign changes; build maximal kept runs. Closed lines: if any part is erased, rotate the ring to start at the first kept point after an erased stretch and treat as open. Classify kinds with `isFillKind` (lib/fills.ts) and `isStampKind` (lib/symbols.ts); fill hit = any path point inside the polygon (even-odd) or any outline segment within radius of the path.

**Goal:** One wasm call applies an `EraseResult` as one undoable edit in a view.

**Files:** Modify `crates/cave-draw/src/lib.rs` (add `copy_stroke_fields`), `crates/cave-wasm/src/lib.rs` (add `erase_lines`, test).

**Acceptance Criteria:**
- [ ] `erase_lines(view, target, adjusted, json)` with `{remove:[id], edits:[{id, points, widths}], adds:[{from, points, widths}]}` removes, reshapes (via `edit_stroke`, with the right frames per view as `edit_line_with` does), and adds pieces (via `map_line` / `profile_sketch` / `section_sketch` with the `from` line's kind, run or station and view; then `with_closed(false)`, then `copy_stroke_fields`) as ONE `doc.edit`, recorded with `record_edit(view, ...)`.
